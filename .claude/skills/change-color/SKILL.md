# サイトカラー変更スキル

ユーザーの要望（$ARGUMENTS）をもとに、サイト全体の配色を変更する。

引数が空の場合は、どんな雰囲気のカラーにしたいかをユーザーに確認してから進めること。

## 手順

### 1. パレットの設計

要望の雰囲気から、以下のロールに対応するカラーパレットを **ダーク／ライトの両テーマ分** 設計する：

- `--color-bg` / `--color-surface` / `--color-surface-2`（背景の階層）
- `--color-border`（区切り線）
- `--color-accent` / `--color-accent-2`（メイン／サブアクセント）
- `--color-text` / `--color-text-muted`（本文／補足テキスト）

設計時の必須条件：
- 本文テキストと背景のコントラスト比は WCAG AA（4.5:1）以上を目安にする
- アクセント2色は同系統の濃淡ではなく、互いに引き立つ組み合わせにする（グラデーションで併用されるため）
- ライトテーマはダークの単純反転ではなく、彩度・明度を調整する

### 2. CSS変数の更新

`src/styles/base.css` の `:root`（ダーク）と `[data-theme="light"]`（ライト）の両ブロックを更新する。片方だけの変更は禁止。

### 3. ハードコードされた派生色の更新

CSS変数以外に、旧アクセント色由来の色値が直接書かれている箇所がある。**変更前のアクセント色のRGB値で `src/` 全体を grep し、漏れなく置き換えること。** 既知の箇所：

- `rgba(124, 106, 247, …)` … 旧アクセント #7c6af7 由来。hero / skills / certifications / gamejams / work-detail / utilities の各CSSに点在
- `rgba(247, 106, 200, …)` … 旧アクセント2 #f76ac8 由来（hero.css のグラデーション）
- `src/styles/header.css` の `rgba(13, 13, 20, 0.85)` … ダーク背景色由来の半透明ヘッダー
- `src/styles/base.css` の `[data-theme="light"] .header` の `rgba(244, 244, 248, 0.88)` … ライト背景色由来

置き換え時は元のアルファ値を維持する。

### 4. 変更しないもの（要望に含まれない限り）

以下は状態を示すセマンティックカラーなので、明示的な要望がなければ変更しない：

- `src/components/Certifications.tsx` の資格ステータス色（緑・青・紫・黄）
- `src/components/Skills.tsx` のスキルレベル色
- `src/styles/gamejams.css` の受賞バッジ色（黄）

### 5. 検証

1. `npm run build` が通ることを確認する
2. 開発サーバーで表示確認できる場合は、ダーク／ライト両テーマを切り替えて、テキストの可読性とアクセント色の見え方を確認する

## コミットに関するルール

- **自動コミットは禁止。** `git commit` を実行してはいけない
- 代わりに、変更内容をまとめたコミットメッセージ案を作成してユーザーに提示する（変更の意図＝どんな雰囲気への変更かを1行目に含める）
- コミットの実行はユーザー自身が行う

## Git CLI の利用

`gh` コマンドによる Issue 作成・PR 操作など、コミット以外の Git/GitHub 操作には制限を設けない。必要に応じて利用してよい。
